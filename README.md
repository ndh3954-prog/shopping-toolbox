# 부업 툴박스 (shopping-toolbox)

쿠팡/네이버쇼핑 셀러(농수산물 도매, 병행수입, 사입)를 위한 개인용 툴 대시보드.
단일 HTML 파일 + localStorage 기반, 서버 없음.

## 배포

- **배포 주소**: https://ndh3954-prog.github.io/shopping-toolbox/ (GitHub Pages, `main` 브랜치 `/ (root)`)
- 저장소: https://github.com/ndh3954-prog/shopping-toolbox
- 로컬 프로젝트 폴더: `~/shopping-toolbox` (main 파일은 `index.html`)
- 수정할 때: `~/shopping-toolbox/index.html`을 고쳐서 커밋 후 `git push` 하면 1~2분 내 위 주소에 자동 반영됨

## 현재 상태

- `index.html` — 지금까지 완성된 버전
- 대시보드에서 툴 2개 실행 가능:
  1. **상세페이지 제작기** — 플랫폼(쿠팡/네이버) x 카테고리(농수산물도매/병행수입/사입/해외구매대행(무재고)/기타)별 규칙이 내장된 프롬프트로 상세페이지 초안 생성. "상세페이지 포맷"을 선택하면 기본 구조 대신 저장해둔 커스텀 섹션 구조로 생성
  2. **썸네일 생성기** — 스타일 프리셋 기반 이미지 프롬프트로 썸네일 이미지 생성
  3. **상세페이지 포맷 관리** — 자주 쓰는 섹션 구조(예: "브랜드 스토리→선물 포인트→상세설명→...")를 이름 붙여 저장/수정/복제/삭제. 상세페이지 제작기에서 드롭다운으로 선택해서 사용
  4. **마진 계산기** — 원가·부자재·배송비·수수료율·광고비율을 입력하면 (a) 판매가 입력 시 실제 마진액/마진율, (b) 목표 마진율 입력 시 추천 판매가를 실시간으로 계산. 계산은 API 호출 없이 브라우저에서 즉시 처리됨
  5. **AI CS 상담원 설정** — 매장명·배송정책·교환반품정책 등 기본 정보를 저장해두면, 문의 유형(배송/교환·환불/원산지/재입고 등)과 고객 문의 내용을 입력할 때마다 매장 정보를 반영한 답변을 AI로 생성. 실제 챗봇 자동응대는 아니고 답변 템플릿을 만들어 복사해 쓰는 용도
  6. **관리자 페이지** — 전체 데이터 현황(각 모듈별 저장 건수), 저장 공간 사용량 추정치, 최근 활동 통합 타임라인(최근 20건)을 한 화면에서 확인. "위험 구역"에 전체 데이터 삭제 버튼(확인창 필요)
  7. **Figma 템플릿 갤러리** — Figma 파일 URL을 붙여넣으면 그 파일의 최상위 프레임들을 이미지로 불러와서 갤러리로 보여줌 (읽기 전용, Figma REST API 직접 호출). 각 카드에서 "Figma에서 열기"로 바로 이동 가능. 최근 연결한 파일은 목록에 저장돼서 재사용 가능
  8. **AI 배너 디자이너** — 상품명 + 브랜드 무드(프리셋/직접입력) + 메인·보조 컬러 + 헤드카피/서브 문구를 입력하면 AI가 상세페이지용 프로모션 배너 이미지를 생성. 상품 사진을 첨부하면 OpenAI·Gemini는 그 사진을 참고해서(이미지 편집/멀티모달 입력) 형태를 유지한 채 새로 디자인함 — Grok은 사진 참고를 지원하지 않아 텍스트 설명만 사용
  9. **AI 디자인 스튜디오** — Canva처럼 텍스트·이미지를 캔버스 위에서 직접 드래그로 옮기고, 크기·글자색·폰트 크기를 조절하는 실제 편집 가능한 디자인 도구. "AI 추천 받기"를 누르면 상품 정보를 바탕으로 AI가 배경색·포인트색·글자색·헤드카피·서브문구를 추천해서 캔버스를 자동으로 구성해주고, 이후 요소를 자유롭게 편집. PNG 다운로드, 디자인 저장(다시 불러와서 이어서 편집 가능)
- 헤더의 **데이터 백업** 버튼 — 상세페이지·썸네일 기록 + 저장된 포맷 + 마진 계산 기록 + CS 답변 기록/매장 정보를 JSON 파일로 내보내기/가져오기 (가져올 때 기존 기록에 추가되며 중복은 자동 제거)
- 헤더의 **네이버 데이터랩 ↗** 링크 — 쇼핑인사이트(카테고리별 검색 트렌드) 페이지를 새 탭으로 바로 열어줌. 상세페이지 만들기 전 키워드/트렌드 참고용
- 헤더의 **☀️ 라이트 모드 / 🌙 다크 모드** 버튼 — 테마 전환, 선택한 테마는 localStorage에 저장되어 다음 방문에도 유지됨 (기본값은 다크 모드)
- 대시보드 카드마다 이모지 아이콘(📝 상세페이지, 🖼️ 썸네일, 🗂️ 포맷 관리, 🧮 마진, 💬 CS, 📊 관리자, 🎨 Figma, 🪧 AI 배너, 🖌️ 디자인 스튜디오)으로 구분
- **API 키 설정 모달** 안의 "🔑 API 키는 어디서, 어떻게 받나요?" 링크 — OpenAI·Gemini·Grok·Figma 4개 서비스의 키 발급 방법을 정리한 페이지로 이동 (각 서비스가 이 앱에서 어디에 쓰이는지, 단계별 발급 방법, 공식 발급 페이지 링크 포함)

## 아키텍처 (중요)

- **AI 호출 방식**: 서버 없이, 브라우저에서 사용자의 API 키로 각 모델사(OpenAI, Google Gemini, xAI Grok)에 **직접 fetch 호출**.
  - API 키는 `localStorage`에만 저장 (키 이름: `toolbox_api_keys`)
  - 텍스트 생성 기록: `toolbox_detailpage_history` (최대 100개)
  - 썸네일 생성 기록: `toolbox_thumbnail_history` (최대 30개, base64라 용량 큼)
  - 저장된 상세페이지 포맷: `toolbox_detailpage_formats`
  - 마진 계산 기록: `toolbox_margin_history` (최대 50개)
  - CS 매장 기본 정보: `toolbox_cs_settings`
  - CS 답변 저장 기록: `toolbox_cs_history` (최대 100개)
  - Figma 최근 연결 파일: `toolbox_figma_files` (최대 10개)
  - 테마 설정(다크/라이트): `toolbox_theme`
  - AI 배너 생성 기록: `toolbox_banner_history` (최대 30개, base64라 용량 큼)
  - AI 디자인 스튜디오 저장 디자인: `toolbox_studio_designs` (최대 15개, Fabric.js JSON + 썸네일이라 용량 큼)
- **AI 배너 디자이너 구현 방식**: 상품 사진이 없으면 기존 썸네일 생성기와 동일하게 텍스트 프롬프트만으로 생성. 사진을 첨부하면 OpenAI는 `POST /v1/images/edits`(FormData로 이미지 첨부)를, Gemini는 `generateContent`에 `inlineData`로 이미지를 함께 넣는 멀티모달 요청을 사용 — 둘 다 실제 fetch 요청 구조까지 테스트 완료
- **AI 디자인 스튜디오 구현 방식**: 외부 라이브러리 [Fabric.js](https://fabricjs.com) v5.3.1을 CDN(cdnjs)으로 불러와 캔버스 편집(드래그/리사이즈/텍스트 인라인 편집)을 구현 — 서버 없이 브라우저에서만 동작. "AI 추천"은 이미지 생성이 아니라 **텍스트 생성 모델**에게 "배경색/포인트색/글자색/헤드카피/서브문구를 JSON으로만 응답하라"고 요청한 뒤 파싱해서 캔버스에 반영하는 방식(이미지 한 장을 생성하는 AI 배너 디자이너와는 다른 접근). 디자인은 `canvas.toJSON()`으로 저장하고 `loadFromJSON()`으로 그대로 복원 — 편집 상태(위치/크기/색/폰트) 전부 유지되는 것까지 확인함
- **Figma 연동**: `api.figma.com`은 CORS 프리플라이트를 포함해 브라우저 직접 호출을 허용함(커스텀 헤더 `X-Figma-Token` 포함해서 실제 테스트 완료). REST API가 읽기 전용이라 파일의 최상위 FRAME/COMPONENT 노드를 `GET /v1/files/:key?depth=2`로 조회 후 `GET /v1/images/:key`로 PNG를 받아오는 "템플릿 갤러리" 형태로 구현. 프레임은 최대 30개까지만 표시
- **이 방식을 선택한 이유**: Claude Artifact(게시) 기능으로 배포하면 보안 정책상 외부 API(OpenAI/Gemini/Grok)로의 직접 네트워크 요청이 막혀서, 지금 설계한 "여러 모델을 직접 골라 쓰는" 구조가 작동하지 않음. 그래서 일반 정적 파일 + 자체 호스팅 방식으로 진행하기로 함.
- **알려진 제약**: 파일을 `file://`로 더블클릭해서 열면 브라우저에 따라 API 호출이 막힐 수 있음 → 로컬 서버(`python -m http.server` 등)나 실제 호스팅(GitHub Pages, Netlify, Vercel 등)에 올려서 사용 권장.
